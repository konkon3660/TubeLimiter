English version below ↓

TubeLimiter는 유튜브 시청 시간을 스스로 정한 한도 안에서 관리하도록 돕는 개인 제작 도구입니다. 이 방침은 앱과 확장 프로그램이 실제로 어떤 데이터를 다루는지를, 코드에 구현된 그대로 설명합니다.

1. 운영자 및 연락처

  • 운영자: TubeLimiter 개발자(개인 개발자)
  • 문의 및 데이터 삭제 요청: jookpower1022@gmail.com

개인정보 관련 문의는 위 이메일로 보내주시면 됩니다.

2. 수집하는 정보

2-1. 계정 정보

로그인은 이메일 주소와 비밀번호로 이루어지며, 인증은 Supabase Auth가 처리합니다. Supabase에는 이메일 주소와 계정 식별자(UUID), 그리고 Supabase가 관리하는 비밀번호 자격증명이 저장됩니다. 비밀번호 원문은 앱이나 확장 프로그램이 저장하지 않습니다. 가입 확인·비밀번호 재설정 메일은 Supabase가 이 이메일 주소로 발송합니다.

로그인은 선택입니다. 로그인하지 않아도 한도 설정, 사용시간 측정, 차단은 기기 안에서 그대로 동작하며 이 경우 서버로 전송되는 데이터는 없습니다. 로그인은 여러 기기(폰 · PC 브라우저) 사이에서 기록을 합치기 위한 기능입니다.

achievements 획득한 뱃지 식별자(예: streak_7, perfect_30)와 획득 시각.

수집하지 않는 것

영상 제목, 영상 ID, 채널명, 시청 기록, 검색어, 페이지 내용, 화면 캡처, 기기 식별자(광고 ID 등), 위치 정보, 연락처, 통화·문자, 사진, 마이크·카메라 데이터는 수집하지도, 저장하지도, 전송하지도 않습니다.

화이트리스트 항목은 사용자가 설정 화면에서 직접 타이핑해 넣은 예외 규칙 문자열이며, 방문 기록을 자동으로 수집한 결과가 아닙니다.

광고 SDK, 분석 SDK, 크래시 리포팅 SDK를 일절 포함하지 않습니다. 앱과 확장 프로그램이 통신하는 외부 서버는 Supabase 하나뿐입니다.

안드로이드에서의 사용시간 감지는 "앱 단위"입니다.

앱은 안드로이드의 UsageStatsManager가 주는 앱 전환 이벤트만 읽고, 그중 유튜브 패키지(com.google.android.youtube)에 해당하지 않는 이벤트는 즉시 버립니다. 다른 앱의 사용 기록은 저장하거나 전송하지 않습니다.

이 방식은 "유튜브 앱이 화면에 떠 있었는가"만 알 수 있을 뿐, 무엇을 보고 있는지는 원리상 알 수 없습니다. 화면 내용을 읽는 접근성 서비스(AccessibilityService)는 사용하지 않습니다. 같은 이유로 안드로이드에서는 Shorts 구분이나 URL 화이트리스트가 지원되지 않습니다.

앱은 android:allowBackup="false"로 설정되어 있어 앱 데이터가 안드로이드 자동 백업으로 클라우드에 올라가지 않습니다.

5. 기기 안에만 남는 데이터

아래 데이터는 서버로 전송되지 않고 기기(안드로이드 DataStore / 크롬 chrome.storage.local)에만 저장됩니다.

  • 날짜별·시간대별 사용 기록, Shorts 사용 기록
  • 긴급 시청 사용 시간과 사용 횟수 기록(횟수는 서버로 올라가지 않습니다)

  • 서버 설정의 로컬 캐시, 마지막 동기화 지점 표시값
  • 로그인한 경우 Supabase 인증 세션 토큰(자동 로그인 유지용)

앱이나 확장 프로그램을 삭제하면 이 로컬 데이터도 함께 사라집니다.

6. 데이터를 보관하는 곳과 접근 범위

  • 서버 데이터는 Supabase(데이터베이스 · 인증 호스팅)에 저장됩니다. Supabase는 이 서비스의 유일한 외부 처리자이며, 개인정보 처리 방침은 https://supabase.com/privacy에서 확인할 수 있습니다.
  • 네 개 테이블 모두 Postgres의 행 수준 보안(RLS)이 켜져 있고, 정책은 auth.uid() = user_id인 행에만 읽기·쓰기를 허용합니다. 즉, 로그인한 본인 계정의 행만 읽고 쓸 수 있습니다.
  • 데이터를 판매하지 않으며, 광고주나 데이터 브로커를 포함한 제3자에게 제공·공유하지 않습니다. 법령에 따른 적법한 요구가 있는 경우를 제외하고 외부로 이전하지 않습니다.

9. 보안에 대한 안내

앱과 서버 사이의 통신은 HTTPS로 이루어지며, 서버 데이터 접근은 위에서 설명한 행 수준 보안 정책으로 계정 단위로 제한됩니다. 다만 이 서비스는 개인이 만든 소규모 프로젝트이고, 데이터 저장·암호화·백업의 실질적인 부분은 Supabase의 인프라에 의존합니다. 어떠한 인증이나 외부 감사도 받은 바 없습니다.

TubeLimiter Privacy Policy (English)

Last updated: September 5, 2026
Applies to: the TubeLimiter Android app (com.tubelimiter.app) and the TubeLimiter Chrome extension

TubeLimiter is a small, independently built tool that helps you keep your own YouTube viewing inside a limit you set for yourself. This policy describes exactly what the app and the extension do with data, as implemented in the source code.

1. Who runs this, and how to reach us

  • Operator: the TubeLimiter developer (an individual developer)
  • Contact and data deletion requests: jookpower1022@gmail.com

2. What is collected

2.1 Account information

Sign-in uses an email address and a password, handled by Supabase Auth. Supabase stores your email address, an account identifier (UUID), and the password credential it manages. The app and the extension never store your plaintext password. Sign-up confirmation and password-reset emails are sent by Supabase to that address.

Signing in is optional. Limits, time tracking and blocking all work on the device without an account, and in that case nothing is sent to any server. An account exists only so that records can be combined across devices (phone and desktop browser).

2.2 Data stored on the server (Supabase)

When you are signed in, these four tables are the complete set of what is stored.

TableContents
daily_usage Per-day total YouTube time (usage_ms), Shorts time (shorts_ms, browser only), how much of that was "emergency" viewing (emergency_ms), and an updated-at timestamp. Dates and millisecond counts only — nothing about which videos were watched.
settings The settings you choose yourself: daily limit, per-weekday limits, reset frequency, always-block-Shorts flag, whitelist strings you typed in yourself (browser-only exception rules), emergency-viewing allowance and reset frequency, notification interval and milestone toggle, hardcore mode state and its disable-request timestamp, and scheduled block windows (weekdays plus start/end minute).
streaks Current streak, best streak, last judged date, total successful days, XP, perfect-day count, and current/best perfect-day streaks.
achievements Badge keys you have unlocked (e.g. streak_7, perfect_30) and when.

What is never collected

Video titles, video IDs, channel names, watch history, search queries, page contents, screenshots, device or advertising identifiers, location, contacts, calls or SMS, photos, microphone or camera data. None of these are read, stored, or transmitted.

Whitelist entries are exception rules you type into the settings screen yourself; they are not a record of sites you visited.

There is no advertising SDK, no analytics SDK, and no crash-reporting SDK in either client. Supabase is the only external server either client talks to.

Detection on Android is package-level only.

The app reads app-transition events from Android's UsageStatsManager and immediately discards every event that is not the YouTube package (com.google.android.youtube). Usage of other apps is never stored or transmitted.

This tells the app only whether the YouTube app was on screen. It cannot tell what is being watched. No AccessibilityService (which can read screen contents) is used. For the same reason, Shorts detection and URL whitelists are not supported on Android.

The app sets android:allowBackup="false", so its data is not uploaded to the cloud by Android's automatic backup.

5. Data that stays on your device

The following is stored only on the device (Android DataStore / Chrome chrome.storage.local) and is never sent to the server:

  • Per-day and per-hour usage records, and Shorts usage records
  • Emergency-viewing durations and the number of times used (the count never leaves the device)
  • Current focus mode, manual block and scheduled block state, and notification history
  • A local cache of your settings and the markers for the last sync point
  • If you are signed in, the Supabase session token that keeps you signed in

Uninstalling the app or the extension removes this local data with it.

6. Where data is held, and who can read it

  • Server data is stored with Supabase (hosted database and authentication). Supabase is the only third-party processor involved; its privacy policy is at https://supabase.com/privacy.
  • All four tables have Postgres row-level security enabled, with policies that allow reads and writes only where auth.uid() = user_id. In other words, an account can only ever reach its own rows.
  • Data is not sold, and it is not shared with advertisers, data brokers, or any other third party. It is not transferred elsewhere except where required by law.

7. Retention and deletion

Data is kept until you ask for it to be deleted; there is no automatic expiry.

There is currently no in-app "delete account" button. The app and the extension offer sign-out only.

To have your account and all server records deleted, email jookpower1022@gmail.com from or naming the address you signed up with. Requests are handled within 30 days of confirmation. Deleting the account removes your rows in all four tables as well — every table is tied to the account with on delete cascade.

To remove only the on-device data, uninstall the app or extension, or clear the app's storage on Android.

8. Children

This service is not directed at children and does not knowingly collect personal information from children under 14 (in the Republic of Korea) or under 13 elsewhere. If we learn that such an account exists, it and its data will be deleted. A parent or guardian can request deletion at the contact address above.

9. A note on security

Traffic between the clients and the server uses HTTPS, and access to server data is limited per account by the row-level security policies described above. That said, this is a small project built by one person, and the substance of storage, encryption and backup rests on Supabase's infrastructure. It holds no certification and has undergone no external audit.

10. Changes to this policy

If a feature change alters what data is handled, this document will be updated and the "last updated" date at the top changed. Changes take effect when posted on this page. Significant changes will also be noted in the app or the store listing.
